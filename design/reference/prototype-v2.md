## 1. What v2 is

A single-file browser robot-boxing manager. The player builds a bot from four
part slots, picks a style and a corner crew, then watches it fight a fixed card of
six opponents. During the fight the player issues four corner commands, welds
damage between rounds, taps to get up from knockdowns, and chooses Destroy or
Spare after a stoppage. Fights are 2D side-on, 3 rounds × 45 s by default.

What the overhaul keeps (overhaul-plan §1): the deterministic 60 Hz seeded sim
separate from rendering; the headless bench and sweep method; manager-style
play (commands, welds, Destroy/Spare); the parts economy (makers, set bonuses,
load limit, buy/hire with scrap); and the balance lessons in §13.

## 2. Sim loop and determinism

| Constant | Value | Meaning |
|---|---|---|
| `DT` | 1/60 s | Fixed sim step |
| `COUNT_STEP` | 0.75 s | One referee count |
| `DMG` | 0.42 | Global scale from strike damage to hull damage |
| `RING` | L 120, R 840, SEP 70, corners 175 / 785 | 1D ring in sim units |

- **RNG:** one `mulberry32(seed)` stream per fight (`F.rng`). Every random sim
  decision draws from it, for both fighters, in call order. `Math.random` is used
  only by presentation (particles, crowd flashes, debris, audio).
- **Step order (`stepFight`, line 660):** fight phase steps fighter A, then
  fighter B (B only if A did not end the fight), then `separate()`, then checks
  the round clock. Other phases run `stepCount`, a break tick, or `stepFinisher`.
- **Events:** the sim pushes plain objects onto `F.events` (`windup`, `hit`,
  `miss`, `dodge`, `malf`, `detach`, `offline`, `knockdown`, `count`, `rise`,
  `resume`, `bell`, `round`, `weld`, `end`, `choose`, `fwindup`, `decap`,
  `spare`, `cmd`, `guard`). The renderer consumes them for sparks, debris, text,
  audio and camera; they never feed back into the sim.
- **Headless run (`simulate`, line 687):** creates a fight with `human = -1`,
  steps up to 600 s of ticks until `done`, clears events each step, and rings the
  bell instantly at every break (both crews auto-weld).
- **Live run (`frame`, line 1200):** an accumulator steps the sim at real time
  (max 8 steps per frame). Hit-stop and slow-motion only pause or slow the
  accumulator; they change pacing, not outcomes.

**Replay gap.** A *headless* fight is fully reproducible from (builds, styles,
crews, seed, config). A *live* fight is not: its seed is
`(Date.now() & 0xffff) + seedN` and is not stored, and player commands, reboot
taps, welds and the bell are applied between ticks at real-time moments without
being logged by tick. See flag F3.

## 3. Fight phases and fighter states

**Fight phases:** `fight` → (`count` ↔ `fight`) → `break` → `fight` … →
`finisher` (stoppages only) → `done`. Decisions go straight to `done`.

| State | Duration | Notes |
|---|---|---|
| `idle` | — | Runs `think()` (movement and attack choice) |
| `windup` | `wu / eSpeed` (×0.75 inside a combo) | Strike resolves at the end |
| `strike` | 0.09 s | |
| `recover` | `0.12 / eSpeed` if a combo is queued, else `0.24 / eSpeed` | Pops the next queued punch |
| `block` | attacker's windup + 0.15 s; 1.3 s when Cover up | Regen ×0.6 while blocking |
| `stagger` | 0.38 s | Clears punch and queue |
| `stall` | 0.45–1.3 s | Jams, malfunctions, overheat, short circuit |
| `down` | until count ends | No energy regen |
| `rise` | 0.8 s (count) / 0.9 s (finisher) | |
| `dazed` | finisher only | Loser waiting for the choice |
| `wreck` / `out` | terminal | Destroyed / spared loser |
| `victory` / `slump` | terminal | |
| `fwindup` / `fstrike` | 0.8 s / 0.35 s | Destroy finisher |

`DOWN = {down, wreck, out}`.

### 4.3 Derived stats (`statsOf`, line 378)

```
load       = head.w + arms.w + legs.w          (must be ≤ torso.cap to fight)
total      = load + torso.w
wf         = max(0.55, 1.25 − total / 120)     weight factor on footwork
move       = legs.move × wf
balance    = min(0.85, legs.balance + 0.15 if Hollis set)
aspd       = arms.speed × 1.1 if Kestrel set
armor      = torso.armor + head.armor
hull hp    = torso.hp  (× opponent `hull` multiplier for veterans)
dodge      = head.dodge + legs.dodge
part hp    = head.hp, lead = rear = arms.hp, legs.hp
reliability per part = that part's `rel`
```

### 4.4 Effective stats under damage (line 410)

```
frac(k)    = part hp / part max   (torso → hull / hull max)
eSense     = 0.02 if head lost; 0 while glitched; else sense × max(0.1, frac(head)^0.7)
eSpeed     = aspd × 0.8 if heat > 70
eMove      = move × 0.55 if frac(legs) < 0.4 × 0.3 if legs hp = 0
eBal       = clamp(balance − 0.2 if frac(legs) < 0.4, 0, 0.9)
ePow(arm)  = power × 0.7 if frac(arm) < 0.4
```

## 5. Combat

### 5.1 The fight brain (`think`, line 530)

```
want  = reach × 0.8 + 42                     preferred distance
move:  retreat         if energy < 18% and kite > 0.3
       advance         if distance > want + 4
       retreat × kite  if distance < want − 20 and (reach > opp reach + 6 or kite ≥ 1)
speed = 78 × eMove × (chase when advancing)  units/s
```

Attacks only when distance ≤ reach + 38 and the opponent is not down or rising.
Priority: open counter window → counter; queued Haymaker (enough energy) →
haymaker; else each tick fires with probability `agg × 2 × eSpeed × DT`
(about `agg × 2 × eSpeed` punches per second), the kind drawn from the style mix.
Under Body work, a drawn uppercut becomes a hook.

**Target:** uppercut → head; Head hunt active → head; Body work active → body;
else head with probability `headBias`.

**Combos:** a non-combo, non-haymaker, non-counter punch starts the style's chain
with probability `combo`. Queued punches fire from `recover` while in range
(reach + 40).

### 5.2 Block, dodge, miss

When a punch starts, a defender that is idle (or past half its recover) with more
than 5 energy blocks with probability

```
p_block = min(0.7, eSense × guard × 2 + 0.14 [0 if glitched])
          × 0.5 haymaker | 0.7 jab | 0.55 counter | 1.0 otherwise
```

and holds the block for the attacker's windup + 0.15 s.

At strike time: an arm jam (rolled at windup: arm frac < 0.4 → chance
`(0.4 − frac) × 0.35`) stalls the attacker 0.55 s; a downed or rising defender, or
distance > reach + 46, is a miss; a dodge part dodges with probability `dodge`
while idle or recovering (pushes the defender 16 units).

### 5.3 Damage chain (`resolveStrike`, line 477)

```
raw   = ePow(arm) × mult × (jabMul if jab) × U(0.88, 1.12)
        × 1.30 to head (1.45 under Head hunt)
        × inside (Swarmer 1.22 when distance < reach × 0.75 + 42)
crit  = unblocked only: chance = set crit (Sabre .08) → raw × 1.5
dmg   = raw × 22 / (22 + defender armor)
```

**Blocked:**

```
dmg × 0.45 (haymaker) | breaker 0.35 (non-jab, Brawler) | 0.18
defender energy −= (9 if breaker else 5) × (0.5 if Cover up)
defender arm wear: lead raw × 0.32 × w, rear raw × 0.16 × w
   w = 0.5 Cover up | 0.8 Counter-puncher | 1.0
attacker arm wear: raw × 0.04
counter window 0.8 s: always for Counter-puncher; 70% under Cover up
```

**Landed:**

```
head target: head part −= dmg × 0.55; under Head hunt energy −= dmg × 0.3 × drain
body target: energy −= dmg × (0.75 Body work | 0.5) × drain; legs −= dmg × 0.2
attacker arm wear: raw × 0.025
shock arms: energy −= 4 × drain; 8% short circuit (stall 0.45 s) unless the hit is lethal
```

**Hull and push:**

```
hull −= dmg × DMG (0.42)
defender pushed dir × (3 if blocked else hull dmg × 1.6) × (1 − eBal × 0.7)
```

Note the asymmetry: part damage uses pre-`DMG` values, hull damage is scaled by
0.42, so part pools drain faster relative to their size than the hull.

**Stagger:** unblocked, hull dmg ≥ 5.5, and `rng > eBal + 0.25` → 0.38 s stagger.
**KO:** hull ≤ 0 during the fight phase → KO, "System failure".

### 5.4 Part loss and malfunctions

- **Arm torn off** at 0 hp: lost, queue cleared, current punch cancelled
  (0.5 s stall). Both arms lost → TKO "Both arms torn off".
- **Head or legs at 0 hp:** offline (`offline` event); effects come through the
  effective-stat formulas (head lost → sense 0.02; legs → move ×0.3 and slower
  rising).
- **Malfunctions (`malfCheck`):** every 0.5 s, only when idle, recovering or
  winding up. For each part below 50%, chance
  `(0.5 − frac) × 0.05 × (1.6 − rel)`; the first that fires wins.
  Head → sensor glitch 2 s (sense 0, no free block chance); arm or legs → stall
  0.5 s and 0.8 damage to that part; torso → power surge, stall 0.7 s, −15
  energy.

### 5.5 Energy and heat

```
per tick: heat −= cool × 12 × DT
          energy += regen × (0.7 if hull < 50%) × (0.6 if blocking) × DT
                    (not while winding up, striking or DOWN)
punch:    energy −= cost; heat += heat × (Swarmer 1.25)
heat > 70: hand speed × 0.8
heat ≥ 100: overheat stall 1.3 s, heat → 55
```

A punch is refused if energy < its cost.

## 6. Knockdowns and the count

```
knockdown chance (unblocked, hull dmg ≥ 4.5, hull < 60%):
  kc = (1 − eBal) × (1 − hull%)^1.6 × 0.16
       × (1.0 head | 0.55 body) × (1.6 uppercut/haymaker) × (1.4 crit) × (1.6 Head hunt)
```

Three knockdowns in one round → TKO. Otherwise the phase becomes `count`.

**The count (`stepCount`).** The standing bot walks to its neutral corner. Every
0.75 s the referee counts one and the downed bot gains rise progress:

```
progress += (player: 0.45 + min(5, taps) × 0.32  |  AI: 0.8 + U(0, 0.7))
            × 0.6 if legs hp = 0
need      = 2.4 + 6 × (1 − hull%) + 1.3 × (earlier knockdowns this fight)
rise when progress ≥ need and count ≥ 2 and count < 10;  count 10 → KO "Counted out"
```

A player who does not tap rises slower than the AI (0.45 vs 0.8–1.5 per count);
three or more taps per count beats the AI's average.

**Rise heal.** On rising the bot regains 6% of its max hull. **Intent (confirmed):
anti-instant-KO** — so a risen bot is not finished by the next jab. This is the
one way a knockdown helps the downed bot; see §13 and flag F1.

## 7. Rounds and scoring

- **Round card:** the bot that dealt more hull damage in the round (margin > 0.5)
  wins it 10–9; equal → 10–10. Each knockdown suffered subtracts one; floor 7.
- **Decision:** after the last round, highest total wins. **Tie → better hull %,
  and an exact tie goes to side A** (the player in live fights). See flag F4.
- **Between rounds:** both bots return to their corners; queues, commands and
  focus clear; heat × 0.3; **energy refills fully**; round knockdown count resets;
  welds refill; sensor glitch clears. The AI crew (and in headless runs both
  crews) auto-repairs.
- **Config:** rounds and round length are player-selectable in the garage;
  defaults 3 × 45 s.

### 8.1 Corner commands (`issue`, line 674)

|---|---|---|---|

## 9. The finisher: Destroy or Spare

Only on stoppages (KO, TKO); decisions skip it.

1. **Settle:** the loser goes down, rises after ~1 s and stands dazed; the
   winner walks in.
2. **Choose** (from 2.2 s): the human winner picks Destroy or Spare (keys D / S);
   **auto-spare after 8 s**. The AI winner chooses after 1.4 s, Destroy with its
   style's probability (Brawler .80, Swarmer .60, Counter-puncher .45,
   Out-boxer .30).
3. **Destroy:** 0.8 s windup, then the loser's head is torn off (`wreck`).
   **Spare:** the loser is `out`.

**Intent (confirmed):** the high AI Destroy rates were intended in v2: brawlers
are meant to be brutal. This conflicts with the overhaul target (Destroy under
15% of stoppages, overhaul-plan §11); see flag F2.

## 11. Exit and gating guards

- **Leave fight** during an undecided fight needs a second tap ("Forfeit? Tap
  again"), records a loss, pays no show money and still charges the repair bill.
  Leaving after a result just settles the result.
- **Sandbox** unlocks every part, crew and opponent, but sandbox fights pay
  nothing and never touch the record or unlocks. The toggle is only reachable in
  the garage, so it cannot change mid-fight.
- **Fight button** is disabled while over the load limit, while any equipped
  part or crew is not owned, or for a locked opponent.
- **Settlement** runs once per fight (`G.settled`).

## 12. The test bench

**In the page (line 1030).** "Run 100 fights vs each opponent" runs the player's
*current* build, style and crew against each of the six opponents with seeds
`500 + n × 7919 + i × 31` (n = 0–99, i = opponent index) and the selected round
config, through headless `simulate()`: no corner commands, both crews
auto-welding. It reports win % and stoppages per opponent and the wall time for
600 fights, yielding to the UI between opponents.

**The balance sweep (confirmed: external script, not in this repository).** The
v2 balance pass ran every legal build × every style × the whole card from a
separate harness that loaded the SIM block. That harness is not in the repo, so
the sweep method is documented here but cannot be re-run as-is (flag F5). The
in-page bench cannot measure corner-command value, because it never issues
commands.

## 13. Balance lessons (overhaul-plan §1) against the v2 code

Per the author, this file is the **post-fix** version: the lessons describe what
earlier builds got wrong, and the remaining issues are partial fixes.

| Lesson | What v2's code does now |
|---|---|
| Blocking that costs your own arms makes defense a trap | **Partial fix.** Blocks still wear the blocker's arms (lead 0.32 × raw, rear 0.16 × raw) and cost 5–9 energy; Cover up halves both and usually opens a counter; Counter-punchers take 0.8× wear and always get a counter. Blocked hull damage is only 18%. |
| Energy drain dominated every other factor | Body drain is 0.5 × dmg (0.75 under Body work), Volta set ×1.25, shock −4 per hit, Head hunt +0.3. Energy refills fully every break, which caps how far drain can snowball. The sweep evidence that this is fixed is not in the repo. |
| Knockdowns must never help the downed bot | No energy regen while down; each knockdown costs a card point; the rise threshold grows with each knockdown. **But the riser regains 6% hull** (intended, anti-instant-KO). Flag F1. |
| Exits like Leave fight and Sandbox need guards | Two-tap forfeit counting as a loss with the bill due; Sandbox pays nothing and records nothing (§11). |
| Every player command must measurably help | Head hunt drains energy so it is not a pure loss against body drain (comment at line 496); Cover up reduces wear and opens a counter. Measured only by the external sweep. |

## 14. Gaps and flags for the overhaul

| # | Flag | Why it matters |
|---|---|---|
| F1 | The rise heal (+6% hull) is intended but contradicts "knockdowns must never help the downed bot." | Decide in the combat GDD: keep a smaller version, replace it with a different anti-instant-KO rule (e.g. a short protection window), or drop it. |
| F2 | AI Destroy rates (30–80%) were intended in v2 but conflict with the under-15% target. | The overhaul's Destroy rule needs its own gating (eligibility, reputation, rules per league), not a style roll. |
| F3 | Live fights are not replayable (unstored seed, unlogged command timing). | The Shorts pipeline needs every input logged by tick: commands, taps, welds, bell, finisher choice. |
| F4 | Side-A bias: exact decision ties go to side A; A steps first every tick, so when both strikes land on the same tick A's resolves first (and can end the fight before B acts). | Symmetric step order (or a seeded alternation) and a neutral tiebreak. Measure it in sweeps by mirroring sides. |
| F5 | The sweep harness is not in the repo; the in-page bench cannot measure commands. | Rebuild the sweep as a headless Godot runner from day one, including a per-command scripted-coach mode for the §11 command targets. |
| F6 | The hull bar alone decides KOs. | Conflicts with pillar 1 ("no abstract HP bar decides a fight on its own"). |
| F7 | One shared RNG stream for both fighters and all systems. | Any added roll shifts every later result. Prefer per-fighter or per-system streams so changes stay local and balance diffs stay readable. |
| F8 | Cover up cooldown is 8 s in the sim but drawn against 6 s in the dock. | Display bug only; the overhaul should read cooldowns from data. |
| F9 | Damage does not persist between fights; the repair bill is the only cost. | The overhaul requires persistent damage; the bill becomes a choice of what to fix. |
| F10 | A hit resolved outside the fight phase skips the KO and knockdown checks. | Edge case; the new sim should make phase transitions explicit. |
