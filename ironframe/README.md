# IRONFRAME Asset Pipeline — isolated vertical slice

This directory is a **production tooling workspace**, not a second game engine. It does not change Scrapyard Circuit's index.html or simulation.

## Scope
- Author a real mechanical ATOM robot in Blender (production art must be supplied/approved by an artist).
- Two independent three-quarter facing cameras, identical framing and locked light/ground conventions.
- Render genuine transparent 2048x2048 PNG sequences from 30fps actions.
- Pack trimmed PNGs into atlas pages plus a 60Hz-tick manifest.
- Inspect the outputs using the independent preview in preview/index.html.
- Test detached right forearm as a separate render layer; gameplay consequences are deferred.

## Requirements
Node.js 20+, npm, Python, Blender LTS, an artist-authored Blender file at art/blender/atom_master.blend. Node tooling requires sharp; it is only a developer build dependency, not a runtime dependency of Scrapyard Circuit.

## Commands (run from the ironframe directory)
1. npm install
2. npm test
3. blender -b art/blender/atom_master.blend --python tools/blender/export_frames.py -- --config config/pipeline.json
4. npm run pack
5. npm run preview — then visit http://localhost:8008/preview/

**Stages 3 and 4 are expected to fail until a real ATOM model with correct named actions, view layers, cameras and sockets has been supplied.** The preview shows a missing-art message rather than fabricating images.

## Sources of truth
- config/pipeline.json: source frame counts and required passes
- build/raw/frames-index.json: metadata written only after Blender renders actual files
- build/manifests/atom.manifest.json: packed runtime contract
- docs/IRONFRAME_REPOSITORY_AUDIT.md: existing engine constraints

## Vertical slice
ATOM idle (36 frames), forward_move (18), right_cross (21), heavy_head_impact (18), right forearm intact/detached, and both facings. The PNGs must be real approved 3D renders; no character art is generated by the tooling.

**Not done:** model creation, rigging, motion authoring, Blender execution, atlas validation with real assets, engine integration, gameplay modifications. These are separate production gates.
